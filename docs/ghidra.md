# Ghidra 定位路线

[安装脚本](../autopanel-fix.sh)确认了目标文件 `/usr/bin/autopanel` 和安装前后的 SHA-256。脚本安装的是现成的修复文件，其中没有负责生成该文件的命令。实际修改的函数、分支和阈值需通过原始分析记录或二进制核对。

## 从会员类型定位到上传大小检查

1. 取 [安装页](install.md) 中原始构建的副本，核对 SHA-256。若实际导入 Ghidra 的是原文件经预处理后的副本，同时记录预处理命令和导入文件的 SHA-256。
2. 导入并运行自动分析。搜索 `exp_svip`，查看字符串的交叉引用，记录会员类型处理函数的符号或地址。若该构建搜不到字符串，用原环境中可确认的上传错误文本从调用点回查。
3. 从会员类型处理函数追踪分支与数据流，找到上传链路读取或比较大小阈值的函数。核对回退分支、数值单位、比较方向和边界。如果有多处相同的常量，在索引中记录实际进入比较的那一处及判断依据。
4. 若手头同时有原文件和已验证的修复文件，分别按安装页核对哈希。在可比较的反编译视图中核查候选函数的逻辑差异，记录导入方式、修改点和生成步骤，再用原先失败的样本复测。将实测结果写入[参数索引](parameters.md)。

Ghidra 函数地址应随导入文件 SHA-256 一起记录。跨构建查找时，可以先从字符串引用和调用关系定位，再核对地址及边界行为。
